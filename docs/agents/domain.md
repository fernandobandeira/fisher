# Domain Docs

Read the root [glossary](../../GLOSSARY.md) and the [ADRs](../adr/) that touch the area you're about to work in.

## Use the glossary's vocabulary

Use the glossary's terms in tickets, proposals, tests, and code. If a term you need is missing, raise it before using it.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, name the ADR and explain why the decision should be reopened.
