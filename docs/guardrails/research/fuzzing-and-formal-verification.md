# Where fuzzing and formal verification would help fisher

| Verdict | What fisher should do |
|---|---|
| Adopt now | Schedule weekly release perft (counting legal move sequences to a given depth) at the approved depths `6,5,7,5,5,5`, plus all 100 published mates. |
| Experiment now | Try fresh seeds for comparing legal moves and FEN (the six-field text describing a position). Schedule weekly only if the pilot finds and replays a fault missed by every existing check and the weekly published suite. |
| Adopt after clock qualification | Repeat the `10/1` match at half the hosted runner’s available cores. Defer the three-match design until a runner has at least eight available cores. |
| Use planned work | Use fisher-4yn.4 for search comparisons and fisher-vpp for known gaps in principal variation checks. |
| Defer | Revisit game-history properties, longer UCI histories, worker schedules, FEN fuzzing, pondering and uncovered error paths at their named changes. |
| No fit | Enumerate squares and conventional attack tables directly. Kani adds no needed evidence here. A Lean proof of alpha-beta would leave the Rust implementation unchecked. |

## What the checks observe

Baseline and tool documentation read 2026-11-25, fisher revision `c1ebde9`. Fisher already requires invariants as property tests: a statement must hold over many inputs. Whole-workspace mutation runs on pull requests and weekly. It asks whether the tests detect a changed program. Region coverage records which parts of compiled source execute. [Evidence policy](../../evidence.md) · [Workflow](../../../.github/workflows/check.yml)

**Rules.** Fixed seeds repeat 21 games from the starting position and four from each of five other roots. At every visited position, the test compares check, every legal move and each move’s resulting FEN immediately. For the next ply it reconstructs fisher’s position from the reference FEN. All six stored fields are printed, so a wrong clock or castling right is already visible on the move that changes it. [Position](../../../crates/rules/src/lib.rs) · [Comparison](../../../crates/rules/tests/positions.rs)

**Published results.** The bench checks cumulative node counts through four plies each commit. The kings in all six roots start too far apart for those depths to expose a king stepping beside the other king. Before fisher-j07 widened the reference games, deleting orthogonal king attacks passed ordinary checks. Only deep perft caught it: Position 3 at depth seven gave 178,633,737 against 178,633,661 published. The widened games now catch it too. Ordinary search tests run ten published mates. [Bench](../../../crates/bench/tests/signature.rs) · [Mate tests](../../../crates/search/tests/search.rs)

**UCI.** The threaded suite enumerates 11,111 strings of up to four generated input steps. One step can emit several reports. A separate test queues stop and a second search before delivering two distinct best moves. The history checker's model also explores reader, worker and handler schedules, including report delivery before and after stop. Replaying inputs cannot reproduce the native thread schedule. [Threaded sessions](../../../crates/uci/tests/threaded_session.rs) · [Model and checker](../../../crates/uci/tests/search_history.rs)

The checker and engine accept four- and five-field FENs followed by `moves e2e4`. The UCI session supplies omitted clocks before handing the FEN to the six-field rules parser. Both reject malformed clock fields. [Checker examples](../../../crates/uci/tests/search_history.rs) · [UCI session](../../../crates/uci/src/session.rs)

Fixed bench data, fallible writers, UCI disconnect and spawn failures, constructor guarantees, unreachable branches and inline test code account for the remaining uncovered regions. [Coverage notes](../coverage.md)

## What earns weekly CI time

An independent author chooses each property, expected result and deliberate fault before implementation. The owner approves them and reads the first failing example with its revision. Restore the clean build and verify it passes. Proposed time allowances below are unmeasured on hosted runners.

**Published suite.** Use the existing ignored release tests in a separate weekly job. The ordinary check job has a 15-minute timeout. The approved perft depths took 33.46 s and later 35.55 s locally, excluding mates. Before implementation, choose one published puzzle outside the first ten. Return a wrong best move there on a throwaway build. Require the ordinary suite to pass and the weekly job to name the puzzle. That planted failure demonstrates the job is wired up and covers previously skipped data. [Acceptance record](../../uci-acceptance.md) · [Expected data](../../../expectations/README.md)

**Fresh seeds.** Targeted generation plays legal games from chosen roots. Reuse shakmaty, the independent rules library. Allow one day for the pilot and ten minutes of release execution for one fresh-seed run across the six published roots. Try a fault that rejects an en passant capture when two pawns could make it. First require every existing check **and the weekly deep perft and full mate suite** to pass on the broken copy. If any catches it, the example earns no weekly run. Schedule only if fresh seeds then find a mismatch and the saved root FEN, seed, moves and revision reproduce it. Keep the fixed seeds each commit. [Shakmaty 0.30.3](https://docs.rs/crate/shakmaty/0.30.3/source/README.md)

Adjudicate differences against chess rules and a third implementation. Two libraries can agree on a wrong clock. Perft and mates cannot settle that. Independently count plies since the last capture or pawn move and increment the fullmove number after Black moves. Use owner-approved FENs worked by hand. [Glossary](../../../GLOSSARY.md)

**Match pilot.** Manual acceptance already includes 1,000-game self-play. Fisher-5sg.10 requires 1,000 release games *each* at `2+0.05`, `2` and `10/1`, eight at a time, switching colors across paired openings, with runner `timemargin 0`. One loss on time blocks its merge. The weekly `10/1` match tests whether later revisions still play within that time control. Keep the runner version, settings, game records, warning log and independent legal replay. SPRT, a sequential probability ratio test, answers a separate question about strength. [Match recipe](../../uci-acceptance.md) · [Evidence policy](../../evidence.md)

The four-core hosted runners rejected concurrency eight at startup, so the three-match design remains [deferred](../deferred.md). At concurrency two, all three trial runners finished the 1,000 `10/1` games in 43 to 45 minutes, with normal terminations, zero losses on time, legal replay, and only the expected threefold repetition warnings. [Three-match trial runs](https://github.com/fernandobandeira/fisher/actions/runs/45660184617) · [Half-core trial runs](https://github.com/fernandobandeira/fisher/actions/runs/45660514862)

On a throwaway build, a two-second delay in White’s best move on move 10 gave 580 recorded losses on time on that move before the match reached its one-hour cap. The ordinary `check` job passed on that build. [Wiring run](https://github.com/fernandobandeira/fisher/actions/runs/45668736462) · [Ordinary check](https://github.com/fernandobandeira/fisher/actions/runs/45668736508/job/139397898687)

## Search and deferred tools

Today’s generated search comparison covers 36 positions at depth two. Independent replay already rejects an illegal later move. Fisher-4yn.4 plans depths one to three every commit, four to five and all 100 mates in release, with deliberate failures. Its expected score comes from fisher’s own plain minimax over fisher’s rules. Both searches can share mistakes. Published mates, hand-reasoned examples including one exact pruned node count, and plain minimax totals anchored to perft provide outside answers. A correct cutoff keeps the root move and score while changing the node count. The bench signature records that change. The old exact four-ply total applies to plain minimax. Material scores lose their authority when fisher-3k5 changes evaluation. [Search tests](../../../crates/search/tests/search.rs) · [Variation replay](../../../crates/search/tests/support/principal_variation.rs)

The [deferred guardrails](../deferred.md) give each trigger and first experiment. For each tool trial, allow one day locally and ten minutes per invocation. The independent author specifies the property and the owner reviews the counterexample before allocating CI time.

- **Proptest** generates inputs for an approved property. Carry games forward once rules store repetition history, a hash or make/unmake data. For UCI, add generated histories only for a demonstrated gap beyond both existing schedule tests and a deterministic regression. [Proptest 1.12.0](https://docs.rs/proptest/1.12.0/proptest/)
- **Loom** controls instrumented synchronization: replacement thread and lock operations that let tests choose the order of execution. Today events enter one channel and one loop. Try Loom when multiple workers can influence the published move. Fisher-a2q.2 later declares the Threads option. Bound preemptions (switches away from runnable threads) and record that bound. This proposed test observes publication order, not elapsed time. **Shuttle** samples replayable schedules if Loom takes too long. Passing samples leave other orders unexplored. [Loom 0.7.3](https://github.com/tokio-rs/loom/blob/v0.7.3/src/lib.rs) · [Shuttle 0.9.10](https://docs.rs/shuttle/0.9.10/shuttle/)
- **libFuzzer** changes a corpus (saved inputs) to reach new code. cargo-fuzz needs a separate nightly toolchain beside stable Rust 1.99.1. Check “never panics” separately from agreement with an independent parser on the same input under the settled acceptance rules. Workspace lints deny panic, unwrap, expect and unchecked indexing. An existing parser example already rejects five fields. Choose the fault only after fisher-og6, and require the parser examples to miss it. [Parser examples](../../../crates/rules/tests/positions.rs) · [cargo-fuzz 0.13.2](https://github.com/rust-fuzz/cargo-fuzz/blob/0.13.2/README.md) · [LLVM 23.1.6](https://github.com/llvm/llvm-project/blob/llvmorg-23.1.6/llvm/docs/LibFuzzer.md)
- **TLA+** describes protocol transitions. **TLC**, its checker, explores finite models. At pondering (fisher-2ha), compare a premature move-release trace with a Rust transcript. Maintaining that correspondence costs more than checking the model alone. [TLC guide](https://docs.tlapl.us/using:tlc:start) · [TLA+ distribution 1.7.4, TLC 2.19](https://github.com/tlaplus/tlaplus/blob/v1.7.4/tlatools/org.lamport.tlatools/src/tlc2/TLCGlobals.java)
- **Kani** checks Rust assertions over symbolic inputs, values standing for every input admitted by a harness (a small verification entry point). All 64 squares and even a corner rook’s 4,096 relevant occupancies can be enumerated against an independent ray walk. No Kani trigger or CI allocation. **Lean** checks formal proofs. Alpha-beta correctness is published. Maintaining a second formalization and its correspondence to Rust buys less here than testing fisher’s implementation. [Kani 0.68.0](https://github.com/model-checking/kani/blob/kani-0.68.0/README.md) · [Lean 4.36.0](https://lean-lang.org/doc/reference/4.36.0/) · [Knuth and Moore](https://www.sciencedirect.com/science/article/pii/0004370275900193)
